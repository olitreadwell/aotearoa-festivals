# Workflow: Building a New Component

Five steps. Skip none.

## 1. Start with Tailwind

Sketch the component using Tailwind utilities directly in JSX. Get the structure and layout right before naming anything.

```tsx
export function PricingCard({ tier }: { tier: Tier }): React.ReactElement {
  return (
    <div className="flex flex-col gap-4 rounded-lg border border-neutral-200 bg-white p-6">
      <h3 className="text-lg font-semibold">{tier.name}</h3>
      <p className="text-3xl font-bold">${tier.price}/mo</p>
      <ul className="space-y-2">
        {tier.features.map((f) => <li key={f}>{f}</li>)}
      </ul>
      <button className="mt-auto rounded bg-neutral-900 px-4 py-2 text-white">
        Choose plan
      </button>
    </div>
  );
}
```

It works. Ship to localhost. Keep going.

## 2. Identify complex patterns

Hit a moment where the className grows past readable, or you need a variant, or hover does three things at once.

In the example above: the card needs `tier === 'featured'` to render with a different border color, lifted shadow, and a "popular" tag. That's a *variant*. Pull it out.

## 3. Create a component SCSS file

`src/styles/components/_pricing-card.scss`:

```scss
@use '../abstracts/mixins' as *;
@use '../abstracts/functions' as *;

.numeral-pricing-card {
  border: 1px solid var(--color-border);
  border-radius: var(--radius-md);
  background: var(--color-bg);
  padding: var(--spacing-md);

  transition:
    border-color var(--duration-200) var(--ease-in-out),
    transform var(--duration-200) var(--ease-out);

  &-featured {
    border-color: var(--color-fg);
    box-shadow: 0 4px 24px rgba(0, 0, 0, 0.08);
  }

  @include hover {
    &:hover { transform: translateY(-2px); }
  }
}
```

Identity, variants, complex state — all named, all in one file.

## 4. Wire it into `main.scss`

```scss
// packages/ui/src/styles/main.scss

@use 'abstracts/variables';
@use 'abstracts/typography';
@use 'global/global';
@use 'components/button';
@use 'components/pricing-card';  // add this line
```

If you skip this step the styles don't ship.

## 5. Combine in the component via `cn()`

```tsx
import { cn } from '@numeral/ui';

export function PricingCard({ tier }: { tier: Tier }): React.ReactElement {
  const featured = tier.id === 'pro';

  return (
    <div
      className={cn(
        'numeral-pricing-card',
        featured && 'numeral-pricing-card-featured',
      )}
    >
      <h3 className="numeral-heading-lg">{tier.name}</h3>
      <p className="numeral-heading-2xl">${tier.price}/mo</p>
      <ul className="flex flex-col gap-2">
        {tier.features.map((f) => <li key={f} className="numeral-paragraph-sm">{f}</li>)}
      </ul>
      <button className="numeral-button numeral-button-primary mt-auto">
        Choose plan
      </button>
    </div>
  );
}
```

The TSX reads top-to-bottom as content. The styling is named, traceable, and variant-aware.

## Don't overthink it

Most components never reach step 3. A one-off section on a landing page is fine with Tailwind utilities — it has no variants, no reuse, no states beyond hover. Save SCSS for the things that earn it.
